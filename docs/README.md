# Project Docs

These documents are the source of truth for SafeSite AI. Read them before changing the product or the demo app,
and keep them in sync when decisions change.

| File | Purpose |
|------|---------|
| [PROJECT_SUMMARY.md](PROJECT_SUMMARY.md) | Product scope: problem, the three core features, target customers, business model, current stage |
| [DESIGN.md](DESIGN.md) | Visual rules: color/type/spacing tokens, components, the design rules ("Do's and Don'ts") |
| [summary.md](summary.md) | Early review of the design reference, including known inconsistencies in `DESIGN.md` |
| [STARTUP_THESIS.md](STARTUP_THESIS.md) | Startup verdict and positioning, ICP, what must be proven, **claims we don't make**, customer-discovery questions |
| [research/LITERATURE_REVIEW.md](research/LITERATURE_REVIEW.md) | English digest of the literature review PDF (safety, FDI, procurement, CV competition) |
| [research/FACT_CHECK.md](research/FACT_CHECK.md) | Every statistic we use, its primary source and status (verified / corrected / unverified) |

**Rule:** any number shown on the `/evidence` page, in the pitch or in these docs needs a row in `research/FACT_CHECK.md`. Use the `/verify-stat` and `/challenge-claim` project skills (in `.claude/skills/`) to check and stress-test claims.

How to run the demo app is covered in the root [README.md](../README.md).
